## 成長画像の組み込み・開発確認（2026-09-25）

- 新規開始は必ず0 EXPの卵。10 EXPであかちゃん、30 EXPでこねこ、60 EXPでおとなになります。次の段階に必要な追加EXPは10 / 20 / 30で、ゲージは現在の段階からの進み具合を表示します。
- あかちゃんは丸い大きな顔・短い手足、こねこは伸びた体つきの別画像です。やること画面にも同じ成長段階を反映します。内蔵image_genで生成した素材とプロンプトは assets/pets/README.md に記録しています。
- 通常URLには開発ツールもリセットボタンも出ません。確認時だけURL末尾に `?dev=growth` を付けて開き、ブラウザーの開発者コンソールで次を実行します。URLを開くだけでは何もリセットされません。

```js
window.makopetDev.resetGrowth('RESET_GROWTH')
```

成長EXPと経験値付与済み記録だけをリセットします。教材・今日の評価・ポイント・ごはん・衣装・装備は維持します。リセット後は同じ教材の評価を再確定して成長EXPを確認できます（ポイントの重複加算はありません）。翌日の学習も通常どおり記録できます。

最初のリセット前の成長データは `makopet_impl_v10_growth_reset_backup` に保存されます。繰り返しリセットしてもこのバックアップは上書きしません。戻す場合は同じ開発用URLのコンソールで実行します。

```js
window.makopetDev.restoreGrowth('RESTORE_GROWTH')
```

通常URLに戻ると開発ツールは無効になります。バックアップや保存に失敗した場合はリセットせず、元の状態を維持します。

`node tests/stage1.cjs` は既存機能の回帰テストと成長テストをまとめて実行します。`tests/growth-flow.cjs` では開発用リセットを実行後、学習評価を12回記録し、0→10→30→60 EXPの順に見た目・ゲージ・保存が変わることを確認します。2日目はテスト用時計で日付を進めます。確認画像は `screenshots/growth/` に保存します。テストは独立したブラウザーを使い、実ユーザーの保存データを変更しません。

## 第2段階：おへやと育成（2026-09-24）

- おへやを全面改修。既存の猫イラストをSVGのクリップで表示し、背景・猫・装備・操作UIを分離しました。背景は従来のピンクのカーテン、窓、ラグ、家具の雰囲気を継いだ `room-backdrop.svg` です。画像に焼き込まれていたポイントやナビは表示しません。
- 猫の名前は「こむぎ」。`pet.name` に保存し、おへやに表示します。名前の変更画面は未実装です。リボン・メガネ・帽子は猫と一緒に拡大縮小します。
- 新規データはたまご（0 EXP）から開始。既存の保存データは、これまでの猫を失わないよう、あかちゃん（10 EXP）として引き継ぎます。従来のポイント、満腹度、教材、装備、所持品は移行時に変更しません。過去の学習履歴からの経験値の遡及計算はしません。

| 成長段階 | 累計経験値 |
|---|---:|
| たまご | 0〜9 EXP |
| あかちゃん | 10〜29 EXP |
| こねこ | 30〜59 EXP |
| おとな | 60 EXP〜 |

- 学習1ptにつき1 EXP、0ptは加算なし。同じ日・教材では、その日すでに付与した最高評価を超えた分だけ加算します。例：3→1→3は合計3 EXP、続けて5にすると合計5 EXP。評価を下げても猫は退化しません。所持ポイントの差分計算は従来どおりです。
- `pet.xp` と `pet.learningCredits` を追加。成長段階は累計経験値から算出します。日付が変わっても経験値と装備は維持されます。移行日の既存評価は加算済み扱いで登録し、同じ評価の再保存で経験値を増やしません。
- 生まれた猫は、学習で新たに1 EXPを得るごとに満腹度が1減ります（下限0）。空腹による退化や病気などのペナルティはありません。ごはんを使うと既存の回復量に加えて2 EXPを得られます。満腹時には食べ物を消費しません。たまごの間は学習で孵化を目指し、ごはんと着せ替えは孵化後に使えます。購入済みの品物は残ります。
- 成長ゲージ、次の段階までの経験値、満腹度ゲージを表示。成長時は「おめでとう！」を短く表示します。あかちゃん・こねこは専用の生成画像へ切り替え、おとなは元の猫イラストを表示します。顔と体の比率・手足の長さが異なり、装備も段階ごとの位置に合わせます。猫の種類追加・図鑑刷新は今回の対象外です。
- 学習・食事の保存失敗時は、ポイント・満腹度・経験値・使用数を変更前に戻し、成功演出を出しません。
- `node tests/stage1.cjs` は第1段階の回帰テストに加え、`tests/stage2.cjs` の育成テストも実行します。新規開始、旧データ移行、4段階の成長、重複獲得防止、食事、装備、日付切り替え、保存失敗、スマートフォン幅を確認します。

## 第1段階（2026-09-24）

- 「やること」は所持ポイント・今日の進捗、大きな猫と吹き出し、コンパクトな教材カードの順に表示します。カードには科目・教材名・進捗バー・今日の状態と「できた！」を表示し、評価ボタンは通常画面に置きません。
- カードを押すと評価パネルを開き、6段階から選んで「これで決定！」で保存します。選択だけ・キャンセルではポイントを変更しません。教材・ページ進捗の編集もこのパネルから開けます。
- 確定後は実際の差分ポイントを約2秒表示。再評価による重複加算はせず、保存失敗時は評価を戻し、成功演出を表示しません。動きを減らす端末設定にも対応します。
- 保存形式には任意項目 `ratedDate` を追加し、未評価と明示的な0pt「おやすみ」を区別します。既存の `score` は0〜5の数値のままです。
- 0〜5ptの数値は維持し、「おやすみ」「ちょっとできた」「こつこつできた」「目標までできた」「もっとできた」「とってもがんばった」を表示します。
- `.hidden`、モーダル、通知、背景のスクロール抑止、キーボード操作を修正。通常画面はページ全体をスクロールし、4つのナビゲーションを下部固定します。
- おへや・ショップ・図鑑の内容と商品は維持。トップの猫も既存画像を利用し、装備を反映します。
- 保存キーは従来の `makopet_impl_v10` のままです。同じサイト・ブラウザーで開くと教材、所持品、装備、ポイントを引き継ぎます。更新前のJSONは、保存領域に余裕があれば `makopet_impl_v10_before_makopet2` に1回だけ退避します。
- 日付を持たない旧データは初回の評価を維持。以後、端末のローカル日付が変わると当日の評価・ポイントだけをリセットし、前日の教材と評価を `dailyHistory` に保存します。所持ポイント・所持品・進捗はリセットしません。履歴の閲覧UIは次段階です。
- 使用済みポイントによって残高が負になる評価訂正は防止します。教材削除は2回押して確定し、獲得済みポイントを維持します。
- 孵化や成長システムの追加は今回の対象外です。以下の従来ロードマップには未実装の構想も含まれます。

## まこペット2・第3段階：ショップ

- ごはん／きせかえの2タブ、商品画像、所持数、購入済み・不足ポイントを表示。
- ごはんは購入時に持ち物へ追加。食べる操作とEXP加算は従来どおりおへやで行います。
- きせかえは重複購入不可。保存失敗時にはポイントと持ち物を復元します。
- 価格：ごはん5／10／20／40pt、リボン15〜45pt、メガネ20pt、帽子60pt。
- 保存先は従来の `makopet_impl_v10` のまま。食品・装備の日本語キーを維持し、既に持っている商品は再購入不要です。

### 商品を追加する場合

商品情報は `catalog.js` に集約しています。`id` は不変の識別子、`category` は表示タブ、`kind` は用途、`slot` は装着箇所、`price` は価格、`image` は画像です。既存品の `storageKey` は変更しないでください。

`inventory: 'food'` は既存食品データへ加算し、`inventory: 'dress'` は既存装備一覧へ保存します。新種の商品には `inventory: 'items'` を利用でき、ID別の個数を追加項目 `state.items` に保存します。`unique: true` なら重複購入を禁止します。

服・首輪・バッグは新しいwearableのslot、おもちゃ・家具は新しいkindとして区別できます。ただし新しい装着箇所や部屋の配置・遊びの機能は、それぞれ専用の描画・操作処理を実装してから販売してください。今回は既存の食品4種・装備7種のみ販売しています。

### 確認

`tests/stage1.cjs` が既存機能・成長・ショップのブラウザ検証を実行します。Node.js、Playwright、Microsoft Edgeが必要です（Playwrightの配置先はPLAYWRIGHT_MODULEで指定可能）。`tests/stage3.cjs` は購入から使用、残高不足、重複購入、保存失敗、320〜844px幅、キーボードタブ操作を確認します。スマホ表示の画像は `screenshots/shop/` に保存します。


## まこペット2・第4段階：ねこずかん

既存のbook.pngから6種類の猫のイラストをSVGの表示範囲で利用します。原画像は変更しません。種類の定義はcats.jsです。既存の1匹は「くいしんぼうネコ」として引き継ぎます。残り5種の育成開始・種類変更の仕組みは今回追加していないため、通常プレイでは未発見として表示されます。

保存キーはmakopet_impl_v10を維持し、pet.speciesId（種類）とpet.rearingId（1回の育成を識別するID）、collectionを追加します。collection.speciesの種類ごとにseenStages、raisedPetIds、completedPetIds、lastPetNameを保存します。育成回数は開始した育成IDの数で、現在育成中の1回も含みます。再読込や開発用の成長リセットでは増えません。成長履歴はリセット後も思い出として残ります。

引き継ぎ時は現在のEXPまでの段階を履歴として補完します。それ以降は学習・ごはんなどの保存と同時に記録し、保存失敗時は図鑑更新も取り消します。画像が追加されただけでは発見されません。将来新しい育成を開始する際には、新しいrearingIdと対象のspeciesIdを設定してください。

collection.rareColorsとcollection.specialOutfitsは拡張用の独立した記録領域です。色・衣装の安定IDをキーにして条件達成記録を追加できます。今回、購入だけによる自動発見や未実装の収集条件は追加していません。

検証はtests/stage4.cjs（stage1.cjsから実行）。引き継ぎ、未発見、詳細、学習からおとな到達、回数の維持、保存失敗、スマホ幅を確認し、screenshots/collectionに画面を保存します。
